# Feature Specification: 数唱テスト（Digit Span Test）

**Feature Branch**: `001-digit-span-working`

**Created**: 2026-05-16

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - テストパートを選択して練習する (Priority: P1)

ユーザーはTOPページで「順唱」「逆唱」「整列」の3パートから1つを選択し、ルールを確認したうえで2回の練習問題を受ける。

**Why this priority**: テストを始める前にルールと操作方法を把握することが必須であり、すべての機能の起点となる。

**Independent Test**: TOPページを開き、いずれかのパートを選択し、ルール表示と2回の練習問題が順に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** TOPページが表示されている、**When** ユーザーが「順唱」ボタンをタップ、**Then** 順唱のルール説明が表示され、練習問題が2回実施される
2. **Given** パート選択画面、**When** ユーザーが「逆唱」または「整列」を選択、**Then** それぞれのルール説明と練習問題が表示される
3. **Given** 練習問題が2回終了した、**When** 自動的に、**Then** 本番テスト開始ボタンが表示される

---

### User Story 2 - 数字の読み上げと回答入力 (Priority: P1)

ユーザーが開始ボタンを押すと数字が日本語で読み上げられ、読み上げ終了後に30秒のカウントダウンが表示され、数字を入力して回答できる。

**Why this priority**: テストの中核機能であり、これがなければテスト自体が成立しない。

**Independent Test**: 開始ボタンを押し、数字が音声で読み上げられ、カウントダウン中に入力フォームへ数字を入力し、回答ボタンを押すことで1問の全フローを確認できる。

**Acceptance Scenarios**:

1. **Given** テスト画面が表示されている、**When** ユーザーが「開始」ボタンを押す、**Then** 数字が日本語（いち、に、さん…）で順番に読み上げられる
2. **Given** 読み上げが終了した、**When** 自動的に、**Then** 30秒のカウントダウンタイマーが表示される
3. **Given** カウントダウン中、**When** ユーザーが入力フォームに数字を入力して回答ボタンを押す、**Then** 正誤判定が行われ、結果（○または×）が画面下部に追記される
4. **Given** モバイル端末でフォームにフォーカスした、**When** キーパッドが表示される、**Then** 数字専用のキーパッドが表示される

---

### User Story 3 - 進級・打ち切りルールによる自動進行 (Priority: P2)

各桁数で2問ずつ出題され、2問ともに不正解の場合はそのパートが終了し、1問以上正解すれば次の桁数へ進む。

**Why this priority**: テストの採点ロジックと難易度制御の要であり、正確な測定には欠かせない。

**Independent Test**: ある桁数で連続2問不正解したとき、そのパートが終了して次のパートまたは終了画面へ遷移することを確認できる。

**Acceptance Scenarios**:

1. **Given** ある桁数の2問目が終了した、**When** 2問中1問以上正解している、**Then** 次の桁数（+1桁）の問題へ自動的に進む
2. **Given** ある桁数の2問目が終了した、**When** 2問とも不正解、**Then** そのパートが打ち切られ、次パートの練習またはテスト終了画面に遷移する
3. **Given** 順唱または逆唱で通常の最大桁数（順唱9桁・逆唱8桁）まで全問正解して完了した、**When** 自動的に、**Then** ボーナスステージ（10桁以上）へ進む
4. **Given** ボーナスステージで同一桁数の2問連続不正解した、**When** 自動的に、**Then** パートが打ち切られ終了する
5. **Given** ボーナスステージで最大15桁まで完了した、**When** 自動的に、**Then** パートが正常終了する

---

### User Story 4 - 結果履歴の確認とリスタート (Priority: P3)

ユーザーは問題ごとの正誤（○×）が画面下部に蓄積表示されるのを確認でき、テスト終了後にリスタートまたはTOPへ戻ることができる。

**Why this priority**: フィードバックとナビゲーションはユーザー体験を向上させるが、テスト自体の機能には直接影響しない。

**Independent Test**: 複数問回答した後、画面下部に○×の履歴が表示されていることを確認し、Restartボタンを押すと同パートの最初に戻ることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数問回答した、**When** 画面を確認する、**Then** 問題ごとの○×が下部に蓄積して表示されている
2. **Given** テスト画面、**When** 「Restart」ボタンを押す、**Then** 現在のパートが最初から再開される
3. **Given** テスト画面、**When** 「TOPに戻る」ボタンを押す、**Then** パート選択画面に遷移する

---

### Edge Cases

- 30秒カウントダウンが0になったとき何も入力されていない場合、どうなるか？（自動的に不正解として処理する）
- 各パートの最大桁数（通常：順唱9桁、逆唱8桁、整列8桁）に達した場合、順唱・逆唱はボーナスステージ（10〜15桁）へ進み、整列はパートが正常終了する
- ユーザーが数字以外の文字を入力フォームに入力しようとした場合、入力を受け付けない
- 読み上げ中にユーザーが回答ボタンを押した場合、読み上げ完了まで入力を無効にする（または回答受付前に読み上げが終わることを保証する）
- Web Speech APIが利用できないブラウザでアクセスした場合、エラーメッセージを表示する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはTOPページで「順唱」「逆唱」「整列」の3パートを選択できる画面を表示しなければならない
- **FR-002**: パート選択後、そのパートのルール説明を画面上部に表示しなければならない
- **FR-003**: 各パートの本番開始前に、2回の練習問題を提供しなければならない
- **FR-004**: 開始ボタン押下後、数字を日本語（いち、に、さん…）でブラウザの音声読み上げ機能により読み上げなければならない
- **FR-005**: 読み上げ終了後、30秒のカウントダウンタイマーを表示しなければならない
- **FR-006**: 数字のみを入力できる入力フォームを用意しなければならない（モバイルでは数字専用キーパッドを表示）
- **FR-007**: 入力フォームの右側に回答ボタンを設置しなければならない
- **FR-008**: 画面下部に問題ごとの正誤（○または×）を蓄積して表示しなければならない
- **FR-009**: 各桁数で2問出題し、1問以上正解した場合は次の桁数へ進まなければならない
- **FR-010**: 同一桁数の2問連続不正解でそのパートを打ち切り、次パートまたは終了画面へ遷移しなければならない
- **FR-011**: 整列パートの最大桁数は8桁とし、それを超えて出題しないこと。順唱・逆唱は通常段階（順唱9桁・逆唱8桁）の後にボーナスステージとして最大15桁まで出題できること
- **FR-011b**: 順唱・逆唱のボーナスステージ（10桁以上）では、同一の数字が複数回登場する数列を使用しても構わない
- **FR-012**: 逆唱パートでは、読み上げた数列の逆順を正解とみなさなければならない
- **FR-013**: 整列パートでは、読み上げた数列を昇順に並べ替えたものを正解とみなさなければならない
- **FR-014**: Restartボタンで現在のパートを最初から再開できなければならない
- **FR-015**: TOPに戻るボタンでパート選択画面に戻れなければならない
- **FR-016**: 30秒経過しても未回答の場合、自動的に不正解として処理しなければならない
- **FR-017**: PCおよびモバイル両方の画面サイズに対応したレイアウトを提供しなければならない

### Key Entities

- **パート（Part）**: 順唱・逆唱・整列の3種類。順唱・逆唱はボーナスステージあり（最大15桁）、整列は最大8桁
- **問題（Question）**: 桁数（通常2〜9桁、ボーナス10〜15桁）・問題番号（1問目または2問目）・数列で構成される。ボーナスステージでは数字の重複あり
- **回答（Answer）**: ユーザーが入力した数字列。正解の数列と比較して○×を判定する
- **スコア履歴（History）**: 各問題の○×の記録。1セッション分を画面に蓄積表示する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはTOPページからパートを選択し、最初の問題の読み上げが始まるまで3タップ以内で到達できる
- **SC-002**: 読み上げ終了から回答入力フォームが操作可能になるまで1秒以内である
- **SC-003**: 打ち切りルールおよび進級ルールが100%正確に動作し、誤判定が0件である
- **SC-004**: モバイル端末（iOS/Android）とデスクトップブラウザの両方で問題なく動作する
- **SC-005**: Web Speech APIが利用可能な主要ブラウザ（Chrome, Safari, Edge）で音声読み上げが正常に機能する
- **SC-006**: 30秒カウントダウンの誤差が±1秒以内である

## Assumptions

- ユーザーはWAIS-IVの数唱テストをセルフ練習・学習目的で使用する
- ユーザー認証・データ保存機能は不要（セッション内のみ）
- 問題の数列はランダム生成する（実際のWAIS-IV問題集の数列と完全に一致させる必要はない）
- 順唱は2桁からスタート、逆唱・整列は2桁からスタートする
- Web Speech APIが利用できないブラウザではエラーメッセージを表示し、テストは実施しない
- サーバーサイドの処理は不要（純粋なHTML+JSによるクライアントサイド実装）
- PCとモバイルの両対応はレスポンシブデザインで実現する
- 整列の最大桁数は8桁とする（仕様で「8桁または9桁」と記載されているが、保守的に8桁を採用）
- 順唱・逆唱は通常段階終了後、ボーナスステージとして10〜15桁まで継続する。ボーナスステージでは数字の重複（同一数字が複数回登場）を許容する
- ボーナスステージにも同じ進級・打ち切りルール（2問中1問正解で進級、2問連続不正解で打ち切り）を適用する
